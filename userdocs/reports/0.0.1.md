**Дата:** 2025-11-30

**Модель:** anthropic/claude-4.5-sonnet-20250929 (через OpenRouter)
**Тестовый скрипт:** `userdocs/test_deep_search.py`

## Резюме

Успешно реализована базовая интеграция OpenRouter в Browser-Use. Класс `ChatOpenRouter` работает корректно, агент инициализируется и подключается к API. Выявлена критическая проблема совместимости JSON Schema между browser-use и Anthropic моделями через OpenRouter.

### Статус: ⚠️ ЧАСТИЧНО УСПЕШНО

✅ **Что работает:**
- Инициализация `ChatOpenRouter`
- Подключение к OpenRouter API
- Запуск агента с `provider=openrouter`
- Базовая коммуникация с моделью

❌ **Что не работает:**
- Structured output (JSON Schema) для Anthropic моделей
- Anthropic не поддерживает свойство `minimum` в integer типах

## 2. Результаты тестирования

### 2.1. Успешная инициализация

Агент успешно инициализировался с OpenRouter:

```
INFO [Agent] Starting a browser-use agent with version 0.9.7,
     with provider=openrouter and model=anthropic/claude-4.5-sonnet-20250929
```

### 2.2. Критическая ошибка: JSON Schema несовместимость

**Ошибка:**
```
openai.BadRequestError: Error code: 400 - {
  'error': {
    'message': 'Provider returned error',
    'code': 400,
    'metadata': {
      'raw': '{"type":"error","error":{"type":"invalid_request_error",
              "message":"output_format.schema: For \'integer\' type,
              property \'minimum\' is not supported"}',
      'provider_name': 'Anthropic'
    }
  }
}
```

**Источник проблемы:**
`browser_use/llm/openrouter/chat.py:172` в методе `ainvoke()` при использовании structured output (response_format).

**Причина:**
- Browser-Use использует `SchemaOptimizer.create_optimized_json_schema()` для создания строгих JSON Schema
- Anthropic API (даже через OpenRouter) не поддерживает некоторые validation constraints:
  - `minimum` для integer типов
  - `maximum` для integer типов
  - Другие validation свойства

### 2.3. Лог файл с полным трейсбеком

Полный лог ошибки включает:
1. Попытку вызова модели через OpenRouter
2. Ошибку 400 от Anthropic provider
3. Retry механизм (пытался 4 раза)
4. Все попытки завершились той же ошибкой schema validation

## 3. Анализ проблемы

### 3.1. Почему это происходит?

1. **Browser-Use генерирует полную JSON Schema** с validation constraints (minimum, maximum, pattern, etc.)
2. **Anthropic Models имеют ограниченную поддержку JSON Schema:**
   - Поддерживают базовые типы (string, integer, boolean, array, object)
   - НЕ поддерживают validation constraints (minimum, maximum, minLength, maxLength, pattern, etc.)
   - Требуют упрощенную схему
3. **OpenRouter проксирует запрос к Anthropic** без модификации schema

### 3.2. Как это решалось ранее?

В старом workaround через `ChatOpenAI` использовались параметры:
```python
llm = ChatOpenAI(
    ...
    remove_min_items_from_schema=True,
    remove_defaults_from_schema=True,
    remove_validation_constraints_from_schema=True,
)
```

Эти параметры есть у `ChatOpenAI`, но **отсутствуют** у `ChatOpenRouter`.

### 3.3. Почему проблема не проявляется с другими провайдерами?

- **OpenAI GPT models:** полная поддержка JSON Schema с validation
- **Google Gemini:** полная поддержка
- **Anthropic напрямую:** browser-use имеет специальную обработку для Anthropic
- **Anthropic через OpenRouter:** нет специальной обработки, используется generic OpenAI-compatible подход

## 4. Варианты решения

### 4.1. ❌ Вариант 1: Добавить параметры schema optimization в ChatOpenRouter

**Недостаток:** Не решает проблему, т.к. `ChatOpenRouter` использует `SchemaOptimizer.create_optimized_json_schema()` напрямую без возможности настройки.

### 4.2. ✅ Вариант 2: Автоматическая детекция Anthropic моделей в ChatOpenRouter

**Решение:**
```python
# В browser_use/llm/openrouter/chat.py

async def ainvoke(self, messages: list[BaseMessage], output_format: type[T] | None = None):
    # Детектим, если это Anthropic модель
    is_anthropic = 'anthropic' in self.model.lower() or 'claude' in self.model.lower()

    if output_format is not None:
        if is_anthropic:
            # Используем упрощенную schema для Anthropic
            schema = SchemaOptimizer.create_optimized_json_schema(
                output_format,
                remove_validation_constraints=True,  # убираем minimum/maximum
                remove_min_items=True,
                remove_defaults=True,
            )
        else:
            # Для других моделей - полная schema
            schema = SchemaOptimizer.create_optimized_json_schema(output_format)
```

### 4.3. ✅ Вариант 3: Параметр в конструкторе ChatOpenRouter

**Решение:**
```python
@dataclass
class ChatOpenRouter(BaseChatModel):
    model: str
    ...
    anthropic_compatible_mode: bool = False  # новый параметр

    async def ainvoke(self, messages, output_format=None):
        if output_format and self.anthropic_compatible_mode:
            schema = SchemaOptimizer.create_optimized_json_schema(
                output_format,
                remove_validation_constraints=True,
            )
```

**Использование:**
```python
llm = ChatOpenRouter(
    model='anthropic/claude-4.5-sonnet-20250929',
    anthropic_compatible_mode=True,  # <- явно указываем
)
```

### 4.4. ✅ Вариант 4: Проверить SchemaOptimizer на наличие нужных параметров

Нужно проверить, поддерживает ли `SchemaOptimizer.create_optimized_json_schema()` параметры для упрощения схемы.
