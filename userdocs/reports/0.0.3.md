## Changes Overview

### 1. Windows Emoji Encoding Fix (BUG-001 - CRITICAL)

**Problem:**
On Windows with Russian locale (cp1251), all emoji characters in log messages caused `UnicodeEncodeError`:
```
UnicodeEncodeError: 'charmap' codec can't encode character '\U0001f517' in position 17
```

**Solution:**
Implemented a multi-layer fix following KISS principle:

1. **Emoji-to-ASCII Mapping** (`browser_use/utils.py`)
   - Created `EMOJI_TO_ASCII` dictionary with 43 emoji mappings
   - Added `sanitize_emoji()` function for text sanitization
   - Added `is_windows_legacy_encoding()` detection function
   - Added `safe_print()` wrapper for non-logging output

2. **Logging Filter** (`browser_use/logging_config.py`)
   - Created `EmojiSanitizingFilter` class
   - Auto-detects Windows legacy encodings (cp1251, cp1252, etc.)
   - Automatically sanitizes log messages and arguments
   - Applied to console handler in `setup_logging()`

3. **Direct Print Statements** (`browser_use/utils.py`)
   - Updated SignalHandler print statements to use ASCII
   - Affected: `windows_handler`, `_handle_second_ctrl_c`, `sigterm_handler`, `wait_for_resume`

**Files Modified:**
- `browser_use/utils.py` - Added emoji utilities and fixed print statements
- `browser_use/logging_config.py` - Added EmojiSanitizingFilter

### 2. Extended Provider Detection

**New Classes** (`browser_use/llm/schema.py`):

1. **SchemaOptimizationProfile** (Enum)
   - `FULL` - Full JSON Schema with all constraints (OpenAI, etc.)
   - `ANTHROPIC` - Remove validation constraints
   - `GOOGLE` - Google Gemini specific
   - `DEEPSEEK` - DeepSeek specific
   - `MINIMAL` - Maximum compatibility

2. **ProviderType** (Enum)
   - `OPENAI`, `ANTHROPIC`, `GOOGLE`, `DEEPSEEK`, `META`, `MISTRAL`, `UNKNOWN`
   - `from_model_name(model: str)` - Auto-detect provider from model name
   - `get_schema_profile()` - Get recommended optimization profile

3. **SchemaOptimizer.create_schema_for_provider()**
   - New method for provider-aware schema creation
   - Accepts either `ProviderType` enum or model name string

**Updated Files:**
- `browser_use/llm/schema.py` - Added enums and new method

## Technical Implementation

### First Principles Applied

1. **Solve at root cause:** Logging filter catches all emoji at output layer
2. **Auto-detection:** Provider type inferred from model name
3. **Backward compatibility:** All existing code continues to work
4. **KISS:** Simple emoji-to-ASCII mapping, no complex encoding logic

### SOLID Principles

1. **Single Responsibility:**
   - `sanitize_emoji()` - only sanitizes text
   - `EmojiSanitizingFilter` - only filters log records
   - `ProviderType` - only handles provider detection

2. **Open/Closed:**
   - New providers can be added to enum without modifying existing code
   - New emoji mappings can be added to dictionary

3. **Dependency Inversion:**
   - Schema optimization depends on abstract ProviderType, not concrete implementations

## Migration Guide

**No migration required.** Version 0.0.3 is a drop-in replacement for 0.0.2.

### New Features Available

**Provider-aware schema creation:**
```python
from browser_use.llm.schema import SchemaOptimizer, ProviderType

# Auto-detect from model name
schema = SchemaOptimizer.create_schema_for_provider(MyModel, 'anthropic/claude-4.5-sonnet')

# Explicit provider type
schema = SchemaOptimizer.create_schema_for_provider(MyModel, ProviderType.GOOGLE)
```

**Provider detection:**
```python
from browser_use.llm.schema import ProviderType

provider = ProviderType.from_model_name('google/gemini-2.0-flash')
print(provider)  # ProviderType.GOOGLE
print(provider.get_schema_profile())  # SchemaOptimizationProfile.GOOGLE
```
